LLM policy
==========

### Transparency:

If you use LLMs at any point for work you wish to contribute to Magic
Lantern, you must inform the Magic Lantern team as to what portions of
your contributions are LLM produced, or LLM guided, etc.

LLMs can be powerful, but are prone to false positives, invented
information, over-confidence.  We need to understand when and how they
are involved, for context when we consider the proposed changes.


### Legal risk:

The international legal system is still adapting to copyright concerns
caused by LLMs.  These models are trained on vast amounts of material,
some of which is copyrighted.  They can produce output that includes
substantial portions of the original material.

Using the US legal system as an example, the decision there is that
LLMs cannot themselves violate copyright, because they're not a legal
person.  The responsibility for avoiding copyright violations falls on
the user of the LLM.

However, the user typically has no ability to learn what sources the LLM was
trained on, and even if they did, cannot practically check such a large
body of data for potential copyright violations.  Thus there is no
practical way for a human to tell if an LLM has produced copyrighted
output.

Therefore, we will not accept code generated by LLMs if it is a
substantial size.  Small amounts of text are not generally considered
legally significant under copyright law.

The GNU organisation says this about legal significance:
```
A change of just a few lines (less than 15 or so) is not legally significant for copyright. A regular series of repeated changes, such as renaming a symbol, is not legally significant even if the symbol has to be renamed in many places. Keep in mind, however, that a series of minor changes by the same person can add up to a significant contribution.
```

We choose to follow this standard for LLM contributions where the code is
directly generated by LLM.

You are allowed to learn from LLM output and use what you have learned to
contribute your own code. You must understand and interpret LLM output, not
directly copy it.  The code you wish to contribute must be your own original
work, or derived from sources with a compatible license, and attributed as
appropriate.
